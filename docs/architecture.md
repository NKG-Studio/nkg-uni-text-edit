# 架构与性能契约

## “无限大文件”的工程定义

这里的“无限大”不是突破操作系统上限，而是：

1. 所有文件大小和偏移使用 `u64`；
2. 打开、阅读和跳转的常驻内存不与文件大小线性相关；
3. 文件内容不整体进入 Rust 堆、WebView、Rope 或 DOM；
4. 全文件操作必须流式执行、可报告进度、可取消；
5. UI 不能因为底层分块而呈现成分页文档；
6. 高亮数量和单次 UI 数据量有显式上限；全部搜索结果落入磁盘索引。

## 分层

```text
原生桌面 UI（egui / eframe）
        │ 仅传递窗口、命中和进度
        ▼
nkg-text-engine
  ├─ FileSource        位置读取与文件快照
  ├─ TextDocument      有界窗口与行边界
  ├─ SparseLineIndex   渐进式稀疏行索引
  ├─ Search            流式、取消、磁盘结果索引
  ├─ BlockDiff         常量缓冲区、有界区段概览
  └─ WindowDiff        有界可见窗口精确对比
        │
        ▼
本地文件系统
```

核心 crate 不依赖任何 UI 框架。桌面层不得绕过核心直接整体读取文件。

## 内存上界

- 默认视口读取：`256 KiB`，硬上限 `8 MiB`；
- 默认搜索块：`4 MiB`，硬上限 `16 MiB`；
- 搜索模式：硬上限 `1 MiB`；
- 完整搜索结果：每条磁盘记录固定 `16 bytes`，UI 单次最多读取 `10,000` 条；
- 当前可见区高亮：默认最多 `10,000` 个 span；
- 块对比：左右各一个固定大小缓冲区；
- 块对比概览：默认最多 `50,000` 个候选区段，超大文件自动放大概览粒度；
- 可见窗口精确对比：默认最多 `4,000,000` 个 LCS 单元格（约 `16 MiB`）；
- 稀疏索引：每 `65,536` 行或 `8 MiB`（先到者）记录一个检查点。

除稀疏索引和显式受限的结果集合外，内存不随文件大小增长。

## 行索引策略

打开文件不扫描全盘，因此刚打开时总行数未知。索引线程从头顺序扫描并逐步发布进度。
在尚未索引到的区域，界面显示字节位置和百分比；索引到达后再提供精确行号。

检查点同时受行跨度和字节跨度约束：

- 短行密集文件不会为每行分配内存；
- 普通日志从最近检查点恢复行号时通常只需扫描数 MiB；
- 单行自身超过扫描预算时允许暂时不显示精确行号，不能因此阻塞界面。

## 搜索策略

第一阶段支持字节字面量和 ASCII 不区分大小写搜索。搜索跨块保留
`pattern_length - 1` 字节重叠区，保证不会漏掉跨块命中。命中通过绝对字节范围表示。

桌面搜索不设置 `10,000` 条之类的隐式截断：每个命中以两个 `u64` 写入临时磁盘文件，
搜索过程中即可读取已经提交的结果。底部结果列表只读取和渲染当前可见区域，文本上下文
再从原文件按需获取并缓存；点击结果后由连续视图定位和高亮。磁盘空间耗尽时必须明确报错，
不能伪装成“已列出全部”。

每次桌面搜索创建独立的磁盘结果索引和可折叠结果组；开始下一次搜索不会覆盖既有结果。
用户删除单组或清空结果后，对应临时索引才随会话释放。

后续正则搜索必须使用同样的分块、取消和磁盘结果契约；多行正则不得隐式读取完整文件。

## 对比策略

块级对比先生成可快速跳转的全局差异概览。I/O 始终使用固定大小缓冲区；当文件过大时，
多个 I/O 块合并为一个概览区域，因此返回区段数量不会随文件大小无限增长。

用户点击候选区段后，只对左右各最多 `1,000` 行的窗口执行精确行级 LCS。矩阵单元格有
硬上限，窗口超限时返回错误并要求缩小范围，禁止对两个百 GB 文件构建完整行序列或
全局编辑图。

## 桌面层

桌面层使用 `egui/eframe`，原因是：

- UI、后台任务和核心均使用 Rust，无需把文本窗口复制到 WebView；
- `ScrollArea::show_rows` 只构建当前可见行；
- 主文本在滚动到窗口边缘时保留锚点并无缝换窗，同时用全文件 `u64` 字节位置提供统一
  滚动概览；界面只显示一个垂直滚动条，用户看到的是一份连续文档，而不是分页；
- 搜索结果将全部命中和各搜索会话标题映射为一个固定行高的虚拟滚动空间，直接按可见行
  从磁盘索引读取，不再额外暴露窗口位置滑杆；
- 原生文件拖放事件直接复用打开文件流程，可一次打开多个文件；
- 搜索、索引、全文件对比在后台线程运行，可进度报告和取消；
- 文件位置用全局字节比例与精确 `u64` 输入共同表示，避免把“总行数未知”伪装成已知。

当前桌面程序是只读查看器。若增加编辑，必须用补丁/日志结构保存局部修改，不允许因一次
按键整体重写上百 GB 文件。

## 验收门槛

在 100 GiB 稀疏文件上：

- 打开过程只读取元数据；
- 能读取开头、任意中间偏移和文件尾；
- 视口分配受配置上限约束；
- 搜索使用固定块缓冲区并可取消；
- 文件大小不会被转换为 `usize` 后用于整体分配；
- 自动化测试覆盖跨块命中、完整结果落盘、连续向前/向后换窗、行对齐、索引进度、取消
  与显式结果截断 API。

耗时和吞吐量与磁盘、缓存及杀毒软件有关，性能基准必须同时记录硬件和冷热缓存状态。
